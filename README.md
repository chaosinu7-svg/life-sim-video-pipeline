# 人生副本 · 长叙事视频生产流水线

把一篇几千字的中文人生故事，做成一条十几分钟、统一漫画 IP、带同步字幕的成片。

这是我自己每天出片在用的生产系统。不是玩具，是从两集真实交付的片子里
（16 分 43 秒 / 155 镜，和 9 分 51 秒 / 114 镜）反过来固化出来的。
里面每一条"踩坑"都对应一次真实事故，不是设想出来的风险。

---

## 它解决什么

做这类视频，真正难的不是"让一张图动起来"，也不是"一次生成很多张图"。
难的是三件事，而现成的工具链一件都没帮你解决：

**一、选什么题。** 同一个账号、同样的制作水平，播放量能差 **1500 倍**——
184 万和 1,167。变量只有选题。什么样的选题会跑赢，是有规律的，
而且和大多数人的直觉相反：**惨不产流量**。

**二、怎么把节奏做紧。** 观众的注意力极其有限。每一幕抛出什么期待、
用多少字兑现它，决定了他划不划走。

**三、怎么不让流水线悄悄骗你。** 这是最贵的一条。渲染成功、脚本零报错、
自动质检全绿的成片，里面可能同时有七个内容错误——而你不逐镜看就永远发现不了。

---

## 铁律

> **自动质检查不出任何内容缺陷。**

成片质检只管黑帧、静音、响度、分辨率、True Peak。我那一集它全绿，
而成片里同时存在：

- 标题卡整段丢失（快闪直接跳进正文）
- 出现剧本里根本不存在的人名
- 屏幕上的数字和旁白说的对不上
- 合同"先公示、两天后才签署"的日期矛盾
- 手机屏幕朝着镜头，而人物的视线也朝着手机——等于他在看背面
- 结尾的记账本换成了另一本，封面还多了个 logo
- 人物该失眠却在笑

**「渲染成功 + 质检全绿」不等于能交付。交片前必须逐镜看。**

## 内容

| 文件 | 说明 |
|---|---|
| `SKILL.md` | 11 步流程、实测语速表、红旗清单、交付规范 |
| `topic-and-narrative.md` | 选题三规律、长片/短片两台机器的区别、六条叙事机制、节奏三条实操 |
| `pitfalls.md` | 十六条踩坑，每条都是真实事故，含复现方法与规避写法 |
| `scripts/` | 分镜装箱、分镜组装、改稿后重映射、几何归一、开头特效、BGM 生成 |

### 脚本

```
pack_beats.py        按实测语速把文案装箱成 4-8 秒的镜头节拍，零超时
build_storyboard.py  节拍 + 画面设计 → 分镜表 + 逐镜提示词（自动处理运动交替、数字白名单）
remap_scenes.py      改稿后把已生成的图按新编号重新对应（不做这步全片配错画面且不报错）
normalize_scenes.py  几何归一：检测黑边 → 裁真内容 → 按 16:9 填满 → 缩放
build_flash.py       开头快闪：12 次切换、白黑频闪、RGB 色差、镜头畸变、颗粒、摇晃
build_opening.py     开头合成：引导语卡 + 快闪 + 选中人生慢推 + 标题定格
gen_bgm_musicgen.py  本地生成 BGM（MusicGen，不需要账号和 API key）
```

## 一条硬数据：语速

手册里的估算值和现实差很远。**先跑一次 TTS 量真值**，再拿去排分镜，
否则片长会估错三到六成。

| 来源 | 字/秒 |
|---|---|
| 手册估算 | 3.4–4.2 |
| Edge TTS 云健 `+0%` 实测 | **4.68** |
| B站头部账号实测 | **5.59 / 6.05** |

对齐头部节奏用 `bodyRate: +20%`，得 5.62。

## 安装

```bash
git clone https://github.com/chaosinu7-svg/life-sim-video-pipeline.git \
  ~/.claude/skills/producing-life-sim-episodes
```

底层流水线（TTS、分镜校验、样式门、渲染、成片质检）走
[hbg-life-simulation](https://github.com/Mr-funny/hbg-life-simulation)（MIT），
需要先装它。本仓库是架在它之上的加固层，不替代它。

依赖：Node 22+、Python 3、FFmpeg、`python3 -m edge_tts`。
